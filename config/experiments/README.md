# Dormant experiment source

These prompts and the unadmitted LOCK template are source material. Nothing here has been executed.

No source code opens these files by name. A future owner passes their exact bytes as strings: `extraction.txt` becomes `system_prompts["extraction"]` and `single-pass.txt` becomes `system_prompts["single_pass"]`, either directly or inside `LiveExperimentConfig.system_prompts`. Runs record the supplied bytes as `prompts/extraction.txt` and `prompts/single_pass.txt` (role keys, underscore). Those run copies are not these template files. No corpus access, credential lookup, client/worker instantiation, provider call, cost, score, custody receipt or human approval is supplied by a template.

The keyless DEV path is `prepare_dev_packet(snapshot_root, out)`, followed by the explicitly fake/replay `run_paired` API when later authorized for runtime validation. DEV preparation writes `packet.json` and `DEV.json`, using the same raw-anchor builder as admitted preparation. It creates no LOCK or rights/custody/access attestation. D4's template writer can supply identity-bound `fixture_not_supplied` failures; those are failures, never measured passing predictions.

For a real locked experiment, an actual authorized owner/custodian must establish source rights and source/gold separation, admit an immutable current-code protocol, lock real provider/model identities and exact prompts, authorize token/time/dollar liabilities, and retain the exact raw LOCK byte digest before inference access. This repository cannot turn agent-authored DEV families into blind human holdout. D7's DEV staging service deliberately refuses heldout/admission claims and cannot supply these missing real-world controls.

`LOCK.template.json` intentionally fails admission: false admission, missing attribution/date/receipts/models/cost and zero digest placeholders. Do not replace those with invented observations. Use actual owner evidence and complete normal activation/validation after Dirty Mode closes. Model/provider identity, prompt bytes, per-request liability, rates/settlement receipts and scope authorization remain explicit later inputs; no current prices are assumed.

`run_live_experiment(protocol_path, snapshot_root, out, *, protocol_digest, caps, system_prompts, models, authorizations=None, transports=None, adapters=None, ledger_root=None, budget_admission=None, settlement_observers=None)` is dormant source. Maps have exactly `extraction` and `single_pass` keys. Missing/disabled owner grants refuse `live_not_authorized` before protocol/source reads or dispatch. Callers must later supply D4's owner-bound `HTTPJSONTransport` for real provenance or an explicitly fixture transport for fake provenance. Real execution also requires an owner-selected durable ledger root outside the source and fresh output; the case stores are `ledger_root/<protocol digest>/<packet digest>/<role>`. Preserve these stores and reconcile actual pending liability through the producer; never move to a fresh root to erase unknown settlement. Fixture-only injection may use output-local state. The orchestrator constructs neither clients nor credentials. No environment variable is read; any future credential binding stays with the separately authorized owner and is never written to artifacts.

It checks the existing unchanged LOCK guards and external raw protocol pin, admits source-control metadata and all source/scope paths before source-file reads, builds one packet, checks both exact request/payload grants, and uses D4's single live producer/ledger. Candidate and single-pass treatments get equal locked total caps in separate treatment ledgers; retries remain within those caps and single-pass permits one logical request. A missing token/cost/time field or unknown pending producer state halts later live dispatch across the experiment; the following arm retains an explicit incomplete/unattempted row. Existing unknown state in either durable case ledger refuses a fresh invocation until reconciled. Accounting balances are never reconstructed/reset by the orchestrator. No label/gold/custody directory is an inference parameter.

Return keys are `preparation_root`, `paired_root`, and `manifest`. The same `verify_paired`/`score_paired` path consumes `paired_root`; there is no alternate live proof model or scorer. Fixture versus live protocol/origin, grant/request/payload/prompt identities and actual attempt-record counts stay explicit. Incomplete outputs keep proposed atoms as unknown plus failure rows. Even a later real call does not mark human or comparative acceptance complete. Full-index utility remains separate from the equal-packet roles.

Real HTTP additionally requires the same content-bound `LiveBudgetAdmission` on the owner transport and durable root, binding protocol, packet, caps and both role authorization IDs. Optional settlement observers must be the already injected owner observers. Pricing, worst-case liability and receipt-backed reconciliation use the single accounting/provider authority; missing observer or admitted dated rates remains unknown and stops later dispatch. Derived settlement cost is distinct from an owner-supplied provider bill. No rates, receipts, ledger or provider operations were executed during construction.
