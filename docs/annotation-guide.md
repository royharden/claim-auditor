# Human annotation guide

No human annotation has occurred in this construction run. Agent-written examples or labels are dev proposals only.

Annotate every atomic README claim, including unsupported kinds and omissions by the candidate extractor. Record the exact frozen source identity, original UTF-8 byte span and quote, parent sentence, structured predicates, negation, conditions, quantities and referents. Do not infer that an example or import statement asserts every behavior it demonstrates. Preserve an unsplittable compound as requiring decomposition rather than inventing independent qualifiers.

Use the precise scoped taxonomy. A declaration claim asks whether syntax declares that symbol, not whether it imports or works. An environment reference is not effective configuration. A literal retry decorator argument is not reliable retry behavior. A positive static proxy cannot verify a stronger runtime statement.

Choose `verified` only when every supported predicate is established with reopenable evidence. Choose `missing` only with a complete bounded absence proof or decisive contrary literal. Choose `partial` only for real supported and unresolved/contradicted predicates; mere subject existence does not make an entirely wrong literal partly correct. Choose `unknown` for unsupported semantics, ambiguous binding, incomplete scope or broken evidence. Negation reverses predicate truth before verdict reduction.

Each `GoldAtom` retains expected verdict/relation, answerability, supported/unresolved/accused predicate IDs, evidence rationale, real annotator identity/type, adjudication date and all disagreements. Accused IDs identify absent/inconsistent predicates; unknown unresolved predicates do not belong in that list. Human rows require actual human evidence review. A single-human protocol does not establish inter-human agreement. Preliminary agent proposals must retain `annotator_type: agent`; never relabel them as human without the actual review.

The independent curator controls heldout source and labels outside the product tree. Before tuning, record rights, original revision, ancestry/family identity, seal date/digests and real access restrictions. A generator/template/ancestor defines one family even after renaming. Blind family aliases must not reveal expected outcomes. Previously exposed source is dev material; later sealing cannot make it unseen. The implementer must not read heldout source/labels to create examples or debug the scorer.

Freeze matcher, taxonomy, packet, provider/model identities, prompts, thresholds, caps and statistical method on dev before heldout access. Run source-only inference first, close it, then expose gold to the scorer. Preserve disagreements and failed releases. Retire disclosed or failed heldout families to dev before further tuning.
