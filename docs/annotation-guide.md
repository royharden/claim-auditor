# Human annotation guide

No human annotation has occurred in this construction run. Agent-written examples or labels are dev proposals only.

The complete atomic denominator must start from the frozen source Snapshot, not candidate-extracted claims. Use `evaluation.annotation.prepare_source_annotation` and explicit manual selection/review. The run-based `rulings.prepare_annotation_package` is labeled assisted candidate review and cannot establish end-to-end extraction recall or complete inventory gold. A candidate omission must remain a manually inventoried atom even when it has no finding.

Annotate every atomic README claim, including unsupported kinds and omissions by the candidate extractor. Record the exact frozen source identity, original UTF-8 byte span and quote, parent sentence, structured predicates, negation, conditions, quantities and referents. Do not infer that an example or import statement asserts every behavior it demonstrates. Preserve an unsplittable compound as requiring decomposition rather than inventing independent qualifiers.

Use the precise scoped taxonomy. A declaration claim asks whether syntax declares that symbol, not whether it imports or works. An environment reference is not effective configuration. A literal retry decorator argument is not reliable retry behavior. A positive static proxy cannot verify a stronger runtime statement.

Choose `verified` only when every supported predicate is established with reopenable evidence. Choose `missing` only with a complete bounded absence proof or decisive contrary literal. Choose `partial` only for real supported and unresolved/contradicted predicates; mere subject existence does not make an entirely wrong literal partly correct. Choose `unknown` for unsupported semantics, ambiguous binding, incomplete scope or broken evidence. Negation reverses predicate truth before verdict reduction.

Each `GoldAtom` retains expected verdict/relation, answerability, supported/unresolved/accused predicate IDs, evidence rationale, real annotator identity/type, adjudication date and all disagreements. Accused IDs identify absent/inconsistent predicates; unknown unresolved predicates do not belong in that list. Human rows require actual human evidence review. A single-human protocol does not establish inter-human agreement. Preliminary agent proposals must retain `annotator_type: agent`; never relabel them as human without the actual review.

The independent curator controls heldout source and labels outside the product tree. Before tuning, record rights, original revision, ancestry/family identity, seal date/digests and real access restrictions. A generator/template/ancestor defines one family even after renaming. Blind family aliases must not reveal expected outcomes. Previously exposed source is dev material; later sealing cannot make it unseen. The implementer must not read heldout source/labels to create examples or debug the scorer.

Freeze matcher, taxonomy, packet, provider/model identities, prompts, thresholds, caps and statistical method on dev before heldout access. Run source-only inference first, close it, then expose gold to the scorer. Preserve disagreements and failed releases. Retire disclosed or failed heldout families to dev before further tuning.

## Append-only annotation source

`claim_auditor.evaluation.rulings` supplies a local operator service; its execution is unverified. Its central wire type is `contracts.AnnotationRuling`, wrapping an existing `GoldAtom`. That reused type name does not make an agent proposal gold. No supplied fixture contains a prefilled `GoldAtom` or human ruling.

Use one ledger per frozen source manifest. Choose a stable annotation subject ID (`atom.gold_id`) and retain it across review revisions. The ruling binds that source manifest, the canonical full Claim digest and the exact evidence-bundle byte digest. `ruling_id` is `stable_id("ruling", fields)` over every other field, using the canonical JSON implementation in `contracts.py`. Dates must be aware and not in the future; a human adjudication date cannot follow the recording date. The evidence bundle includes the evidence and coverage the annotator actually reviewed. A digest identifies those bytes; only reopening the source and the sole citation resolver can establish integrity.

`make_ruling` constructs a judgment without writing it. `append_ruling` and `import_rulings` validate it and append only new records under an exclusive writer lock. A human row requires an actual human review, nonblank `human_action_id`, actual adjudication date and explicit `human_confirmation=True` at the write/import boundary. The flag is an operator attestation, not authentication or proof that a human acted. Automated callers must never set it on a person's behalf. An agent row cannot carry a human action ID.

A revision must name that annotator's latest `supersedes_ruling_id`; existing disagreement text must be retained. Different annotators remain separate rows, including when they disagree. Exact import repetition is a no-op. Changed source/claim/evidence bytes are a conflict, never an implicit revision: retain the old ledger and prepare fresh review in a new ledger. Source changes never inherit a human judgment merely because prose looks similar.

`current_rulings` requires the current manifest digest and maps keyed by exact claim ID, computed independently from reopened Claim/evidence bytes. It returns each annotator's latest judgment; it does not choose a consensus, adjudicate or emit final gold. The independent curator must resolve disagreements after actual review and explicitly admit the scorer input under the real evaluation protocol. Do not use the ledger's own digest values as proof of current bytes.

Bounds: 5,000 rows, 10 MiB total, 256 KiB per row. A busy lock fails immediately; do not steal a lock based on age. Partial/unterminated appends fail closed. Preserve crash artifacts and recover into a new reviewed file; the service never truncates history. Append/import prevalidate a batch, but a machine crash may leave a partial batch or tail. This is an operator-owned ordinary-directory tool, not tamper-proof multi-user storage; file permissions, actual backups, process races and filesystem crash behavior need later validation.

## Independent raw-source inventory

The source-first package copies a verified Snapshot and retains every original README line as an `InventoryBlock`, initially `unparsed`; it invokes no candidate extractor and consumes no candidate claims/findings, model output or expected labels. Scope entries/exclusions identify the available source evidence without resolving a verdict. The human must review prose, headings, code fences, HTML, link definitions and blank lines rather than assuming a parser found all assertions.

In `SOURCE.json`, `candidate_extractor_invoked=false` and `candidate_findings_used=false` describe extractor invocation and candidate-finding consumption during that preparation, not Python package or module initialization; shared helper imports are permitted.

Select nonempty half-open original UTF-8 byte ranges explicitly. Repeated text is not located by search or guessed alignment; the caller supplies the intended occurrence. `RawDocument` is the coordinate authority for UTF-8, LF, CRLF and bare CR. Retain the whole parent context through an explicit parent span and use a parent-local ordinal for each atom. Structured predicates retain subject/module/path/key/expected value, negation, condition, qualifiers and pattern. Their meaning still requires actual review; byte integrity does not establish entailment. IDs use the existing `sentence`/`claim`/`predicate`/`block` stable-ID authority. Incoming predicate IDs are derived afresh from the manual claim, never inherited as a candidate restriction.

Supply a disposition and reason for every raw block. `extracted` means its assertions have been manually inventoried, including explicitly unknowable/unsupported-semantic atoms; it does not mean those claims are verified. `nonassertion` cannot discard an already selected atom. `unsupported` means the block remains unresolved for manual decomposition/review, while `unparsed` means not yet reviewed; both keep `Inventory.complete=False`. Missing blocks/reviews, duplicate/conflicting atoms, changed source/parent spans or forged complete flags refuse or remain visibly incomplete. No tool can determine that a human marked all actual assertions correctly; actual review and later independent acceptance remain essential.

`ManualAnnotation` is the central record containing exact inventory, parent spans, source digest and real actor/action metadata. It is content-addressed and written to a fresh file. A revision retains author/type/family and names its predecessor; previous files are preserved. A human inventory requires an explicit actual action ID and confirmation. An agent proposal cannot be relabeled human by a revision; human source review is a separate attributed record. Preserve the original record chain alongside later label releases.

Human ruling input is accepted only for exact manual atoms from a human-reviewed inventory. Empty evidence bundles can accompany `unknown`; no static index or absence proof is fabricated for them. Nonunknown judgments require reopenable evidence. The sole citation/coverage resolvers validate all supplied evidence; source/claim/evidence changes are conflicts. Completed manual coverage does not make the code scope complete or authorize an absence accusation through a source gap.

Final human export requires complete raw coverage and one explicitly selected latest human ruling for every manual atom, with actual operator ID/action/date/confirmation and adjudication rationale. Competing latest judgments must remain in the selected human ruling's `disagreements` by their ruling IDs; history is also exported intact. The service never automatically chooses consensus, upgrades preliminary agent rows or omits inconvenient atoms. The resulting `gold.jsonl` reuses the scorer's `GoldAtom` schema; it is a later operator release, not a fabricated annotation supplied by this repository.

Agent proposal export is separate, explicitly labeled and retains pending claim/block IDs. `audit_manual_omissions` compares the retained full manual inventory with a later candidate inventory using the existing scorer matcher; candidate duplicates remain ambiguous and absent atoms remain omitted. It does not constrain which manual claims can exist, invoke inference or establish comparative acceptance. Incomplete manual review makes this diagnostic provisional.

## DEV staging boundary

The twelve authored DEV families and all 120 statements remain disclosed and unannotated. `evaluation.custody` contains future local staging functions, not a heldout-custody service. Staging accepts only `DEV_ONLY` provenance and an actual operator-supplied access/rights attestation. Heldout/admission/custody-certification claims are refused. No access receipt has been populated or staged in this construction work.

An opaque alias changes a directory label, not what the author has seen. Select aliases without outcome/kind/family words and retain the alias/provenance mapping in the private control tree. Export only the source snapshot to inference; never include provenance, review prompts, coverage-map, access receipts, rulings, annotation rationale or the separate label tree. A known-filename filter and an operator declaration reduce accidental mixing but cannot prove the absence of hidden labels or semantic leakage. The external curator remains responsible for real separation and independent heldout source.

DEV label staging reopens exact claim/evidence bytes and uses the sole citation/coverage resolver; it preserves all judgment history and does not certify semantic accuracy, actual human work, consensus or scorer admission. A digest-only seal detects changes against a separately retained expected digest; it does not configure ACLs, establish rights or make an exposed family blind. The concrete staging APIs and required attestation fields are in [labeling-package.md](labeling-package.md).
